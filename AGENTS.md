# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Copilot, Cursor, etc.) working in this repo.
Humans: see [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## What this is

A small **static demo website** for a fictional hotel group, **iVvy Venues**, with venues in three
regions: Asia Pacific, Europe and North America. The iVvy sales team uses it to demo iVvy
products embedded in a realistic venue site: each region page links to that region's iVvy
booking engine and meeting booker and embeds its iVvy enquiry widget. It is hosted on GitHub Pages
from the `gh-pages` branch.

## Hard constraints — do not break these

1. **No build step, no dependencies.** Plain HTML, CSS and vanilla JavaScript only. No npm,
   bundlers, frameworks, static-site generators, TypeScript, Sass or CDN-hosted libraries/fonts.
   A salesperson must be able to double-click `site/index.html` and have it work, offline.
   The only remote resources are the iVvy products being demoed (the enquiry widget scripts and
   the booking links); the rest of the site must still render without them.
2. **Relative paths only.** The same files must work unchanged at:
   - `file:///…/site/index.html` (opened from disk)
   - `https://ivvycode.github.io/demowebsite/` (project sub-path)
   - a custom domain root, e.g. `https://demowebsite.ivvy.com/`

   So: never start an internal URL with `/` or `//`, never use `<base>`, and always link to a
   file (`index.html`, not `./` or a folder).
3. **Must run from `file://`.** No `<script type="module">`, no `fetch()`/XHR of local files,
   no service workers, no History API routing (use `#` hashes). Use classic `<script src="…">`
   tags; inline any data.
4. **Two long-lived branches only:** `main` (development) and `gh-pages` (published output).
   Never commit to or edit `gh-pages` directly; it is generated by `scripts/publish.sh`.
   `main` is protected: changes go through a pull request from a short-lived branch, and the
   `check` CI job must pass.
   Do not publish unless a human explicitly asks you to.

## Layout

```
site/                     ← everything that gets published (becomes the root of gh-pages)
  index.html              ← the only HTML page: header, empty <main id="main">, footer, toast
  .nojekyll               ← stops GitHub Pages running Jekyll; keep it
  assets/css/styles.css   ← all styles, incl. self-hosted @font-face rules
  assets/js/main.js       ← all content (data constants) and the hash router
  assets/fonts/*.woff2    ← self-hosted Poppins (400/500/600/700) and Nunito Sans (variable)
  assets/img/             ← logo.png and venue photos (photo-*.jpg)
scripts/check_site.py     ← portability/link checker (Python stdlib only; runs in CI)
scripts/publish.sh        ← copies site/ to gh-pages and pushes
.github/workflows/        ← check.yml (PRs + main), publish.yml (manual "Run workflow")
```

## How the site works

It is a single page. `main.js` renders every view into `<main id="main">` from the URL hash:

| Hash               | View                                  |
|--------------------|---------------------------------------|
| `#/` or empty      | Home: hero, "Our regions" cards, "About us" |
| `#/asia-pacific`   | Region page                           |
| `#/europe`         | Region page                           |
| `#/north-america`  | Region page                           |
| `#spaces`, `#contact`, … | Scrolls to that section on the current view |

`route()` runs on load and on `hashchange`: it renders `homePage()` or `regionPage(key)`, sets
`aria-current="page"` on the matching header nav link (by `data-route`), sets `document.title`
and the hero background, then for region pages calls `renderSpaces()` and `bindRegion()`
(space scroller arrows + `mountWidget()`). An unknown hash that isn't a section id falls back
to home.

A region page has, in order: hero → **Spaces** (horizontal scroller of space cards) →
**Contact our events team** (phone, hours and the iVvy enquiry widget) → **Book instantly**
(booking engine button) and **VIP exclusive** (meeting booker button).

### Data constants in `main.js`

Edit content here rather than in the HTML templates.

- `LINKS` — per region `{ bookingEngine, meetingBooker }` URLs for the two booking buttons.
  A value of `"#"` disables that button: clicking it shows a toast asking for the link.
- `IMG` — photo key → `assets/img/…` path (numbered photos plus `home-hero`, `conference`, `tent`).
- `PHOTOS` — per region, space name → `IMG[…]`. Names must match `REGIONS[…].spaces` exactly;
  a space with no photo shows its kind's icon as a placeholder.
- `HOME_PHOTOS` — photo for each region card on the home page.
- `HERO_PHOTOS` — hero background for `home` and each region.
- `KINDS` — space kinds (`ballroom`, `meeting`, `dining`, `outdoor`) with labels; each has an
  icon in `I`.
- `REGIONS` — per region: `name`, `hotelCount`, `hotel`, `intro`, `phone`, `hours`, and
  `spaces` as `[name, kind]` pairs. Home page stats are computed from this.
- `WIDGETS` — per region iVvy enquiry widget `{ src, region, id }`. `mountWidget()` injects the
  script into `#formCard` with `data-region`, `data-widget-id` and `data-container`, and shows a
  fallback message if it fails to load (e.g. offline).
- `ORDER` — the order regions appear in on the home page.
- `I` — inline SVG icons.

To **add a region**: add the same key to `LINKS`, `PHOTOS`, `HOME_PHOTOS`, `HERO_PHOTOS`,
`REGIONS`, `WIDGETS` and `ORDER`, then add a link to both the header nav (with `data-route`) and
the footer nav in `index.html`.

## Brand and styling

All styles are in `assets/css/styles.css` and follow the iVvy brand. Use the custom properties in
`:root` rather than hard-coding values:

- **Colours:** `--ivvy-dark-green` `#0F331F` (primary background/headings), `--ivvy-green-mid`
  `#99c852` (accent, primary buttons), `--ivvy-green-hover` `#7aaa3a`, `--ivvy-green-light`
  `#CCE3A8`, `--ivvy-white`, `--ivvy-light-gray` `#e5e7eb`, `--ivvy-body-dark` `#666666`
  (body text on white), `--ivvy-body-light` `#e5e7eb` (body text on green), `--ivvy-card-dark`
  `#1a4a2a` (cards on green).
- **Fonts:** `--ivvy-font-heading` Poppins for headings, nav and buttons; `--ivvy-font-body`
  Nunito Sans for body text. Both are self-hosted woff2 files in `assets/fonts/` — never link
  Google Fonts or another font CDN.
- **Layout:** sections alternate **dark green / white**. The header, `.hero`, `.section--alt` and
  footer are dark green; plain `.section` is white. Dark areas redefine the semantic tokens
  (`--page`, `--card`, `--heading`, `--text`, `--border`, …), so components pick up the right
  colours automatically; `.form-card` switches back to light tokens for a white card on green.
  When adding or reordering sections, keep the alternation (e.g. a region page goes hero (green)
  → Spaces (white) → Contact (green) → Booking (white)).
- Prefer existing classes (`section`, `section--alt`, `container`, `section-head`, `btn
  btn-primary` / `btn-outline`, `form-card`, `book-block`, …) over new ones.
- Radii and widths: `--ivvy-container` 1200px, `--ivvy-radius-card` 10px, `--ivvy-radius-btn` 6px.

## Conventions

- The header and footer live once, in `site/index.html`. If you add a 404 page or another HTML
  page, keep the same `<head>`, header and footer as `index.html`.
- Images go in `site/assets/img/` and are referenced relatively. Keep them small (< 300 KB each).
  Provide `alt` text.
- Venue content is fictional. Don't use real customer names, addresses, phone numbers or emails —
  use obviously fake details (e.g. `+61 7 3000 0000`, `example.com`). The iVvy product URLs in
  `LINKS` and `WIDGETS` are real demo accounts; only change them when asked.
- Escape any data inserted into HTML templates with `esc()`.
- 2-space indentation, LF line endings (see `.editorconfig`).

## Before you finish

```bash
python3 scripts/check_site.py
```

It must print `Site check passed.` Then open `site/index.html` from disk and click through home and
each region page, including at a narrow (mobile) width. If you changed `LINKS`, check each region's
**Visit our booking engine** and **Open meeting booker** buttons point to the right URLs.
